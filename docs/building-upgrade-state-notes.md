## Проверенный объём

В текущих исходниках выбираются17 типов обычных существующих зданий (1–18, кроме хижины7). Default сохраняет тип4. В пределах выбранного типа берётся свободное здание наименьшего уровня ниже цели; native-план следующих уровней исключает недоступные предпосылки, нехватку ресурсов с резервом и предметные требования. Пользователь задаёт типы, цель1–24 и резервы еды/дерева/камня/золота в Desktop/Telegram. Один запуск за проверку. Только постоянный строитель `from=born`, свободная запись buildingId=""/endTime=-1. Дополнительный строитель за предметы/гемы не нанимается. Предметные требования и уровень25 пока исключены.

## Состояние и ввод

- Выбор принадлежавшего городу здания подтверждается `@building_menu.selected.id/type/level`, кнопками Info/Upgrade и максимум одной функциональной кнопкой. У каменоломни: btn_CityPopUpUpgrade/btn_FunctionQuarry/btn_CityPopUpInfo. Положение меню других типов привязано к свежей откалиброванной точке здания; положительно проверены ратуша и стена.
- Нажатие по производящему зданию сначала может собрать камень. Повтор выбора допускается только после наблюдённого сброса всех ожидавших производств, увеличения баланса, окончания игровой анимации зачисления и неизменности камеры. Проверенная ground-точка, без смещения к соседним крышам. Попытка сместить точку на35px вверх выбрала музей96; после этого ввод по меню не продолжался, выбор очищен.
- Upgrade(475,365) открывает UpgradeBuilding. Прямые поля: buildingId, btype, curLv, canUpgrade, requireRss, itemType/itemNum. requireRss записи type/num/finalNum; в расчёте используется finalNum и проверяются все резервы.
- Обычный Upgrade(740,410), отдельный от Instant(около545,410). Одна отправка. Результат: целевое здание state2 с будущим endTime, прежний lv, постоянная очередь указывает на тот же buildingId, ровно списана наблюдённая стоимость, гемы/остальные валюты сохранены.
- В BuildQueue.endTime=-1 закодирован срок действия постоянного строителя, **не** время завершения строительства. Таймер стройки — в записи самого здания. Первая попытка наблюдателя ошибочно ожидала одинаковые endTime и закончилась тайм-аутом уже после успешного запуска. Условие исправлено по живым данным;51 сохранённый снимок повторно подтвердил квитанцию. Повторный Engine при занятом строителе не сделал ввода.
