# Mirage — план реализации и проверки

Основание: утверждённое описание `../specs/2026-11-08-mirage-design.md`.

## Порядок

1. Проверить фактическую среду BlueStacks: экземпляры, ADB, root, Android ABI, наличие игры, процесс и библиотеки. Подготовить собственный воспроизводимый диагностический инструмент. Изменения эмулятора сопровождать резервной копией исходной конфигурации. Наличие флагов root не считать доказательством действующего root.
2. Исследовать собственный адаптер состояния игры. Подтвердить чтение реальных полей и их обновление, отмену сеанса и изоляцию экземпляров. Не использовать код Whale/Nexus или выдуманные адреса. Если техническая основа недоступна, зафиксировать конкретный блокер вместо подмены памяти экранным движком.
3. Реализовать ядро: модели, SQLite, конфигурации, события, команды, ограниченный диспетчер, расписания, ротация и адаптеры эмуляторов. Смысл ручной остановки, выключенного экземпляра и смены процесса закрепить тестами.
4. Создать рабочий настольный интерфейс PySide6 по выбранному макету. Все операции ввода-вывода выполняются вне GUI-потока. Данные и ошибки из реальных адаптеров, сохранение черновиков, явная область действия команд.
5. Последовательно реализовать игровые модули с проверяемыми предусловиями и подтверждением результата: помощь альянсу; сбор ресурсов; бесплатные ежедневные действия; обучение; строительство/исследования/лечение; разведка; гемы/варвары/ралли; остальные модули спецификации. Модуль не маркируется рабочим без подтверждения игрового сценария.
6. Подключить Telegram к тем же командам ядра, редактор расписаний, скриншоты и Live. Секреты хранятся локально, владелец проверяется на каждой команде.
7. Проверить интеграции, GUI, аварийные состояния, три реальные игры на этом устройстве и 50 логических сессий на управляемом стенде. Упаковать Windows-сборку, проверить чистый запуск и сохранение настроек. Составить отчёт с фактическими результатами и ограничениями.

## Проверки

- Unit: времена и пересечения слотов, полночь, ручная пауза, отключение расписания, смена экземпляра, смена процесса, изоляция очередей, лимиты и отмена, сохранение/экспорт без секретов.
- Adapter: парсинг реальных конфигураций, привязка стабильного ID, тайм-ауты команд, ADB-переподключение, root, несовместимый профиль, отсутствие процесса.
- Memory: повторные чтения, корректность структуры, идентичность персонажа и процесса, свежесть, изменяющийся таймер, потеря связи.
- GUI: реальные виджеты, переключение экземпляров, черновики, отсутствие блокировки при медленных командах и корректное завершение приложения.
- Integration: подтверждённое действие в игре по каждому модулю; таблица свидетельств отличает живые проверки от имитаций.

## Текущее исследование

- BlueStacks 5.22.285.1013; Nougat64 — 2 vCPU / 2048 МБ, Pie64 — 4 vCPU / 4096 МБ.
- ADB в конфигурации включён, флаги root обоих экземпляров выключены. Порты: 5565 и 5555.
- Установлен Python 3.14 x64. Совместимость зависимостей проверяется до выбора рабочего интерпретатора.
- Официальные API Qt и Frida сверены с текущей документацией. Закрытые реализации ориентиров не исследовались.
