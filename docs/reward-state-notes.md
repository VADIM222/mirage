При возобновлении сначала закрывается уже полученный командир, а новая бесплатная попытка рассматривается отдельно по свежему таймеру. Другие модальные окна/режим10 сундуков не подтверждаются.

Это также новые полные положительные маршруты золотого и экипировочного сундуков. `mirage-tavern-commander-recovery-20261111-v1`.21 целевой тест прошёл; повтор общей EXE-проверки требуется.

Полный набор после исправления —513 тестов/152.81с, новая EXE прошла smoke0. Общий packaged-повторv2 выполняется отдельно; его результат не подменяется исходным Engine-свидетельством.

## Активность окон

- `m_visible` не является самостоятельным признаком активности. После закрытия VIP и RoutineRewardsCollect он оставался `true`.
- `m_unityObj` при этом менялся из userdata в nil. Закрытые таблицы Lua продолжают существовать в UIObjectManager.
- У открытой QuestSystemMainPage собственный `m_visible` отсутствует: используется наследуемое значение. Явное `false` означает скрытие; отсутствие поля нельзя трактовать как скрытие.
- Проверка активности читает поля напрямую, без выполнения Lua/Unity-методов. Наличие живого объекта и отсутствие явного скрытия рассматриваются вместе.
- Контейнеры MapElementHud, MapElementHud3D, CityUIContainerHud, CityReflowUIContainerHud, AlliMarkElementHUD наблюдаются в обычном городе. Они перечислены явно; неизвестные окна блокируют ввод.
- PopupMissionComplete загружается постоянно (`m_alwaysload=true`) и сохраняет Unity-объект даже после исчезновения уведомления. Он исключается только при подтверждённом `TipsState_IDLE=1` и `TipsItems[1].State=TipsItems[2].State=1`. При неизвестном/активном состоянии блокировка остаётся. После этой поправки помощь альянсу подтверждена повторно: 4 → 0.

1. Открытие: `(108,46)` → активна VIPMainPage.
2. Бесплатные очки: `(765,152)` → CanGetFreePoint false и появляется VIPNotice.
3. Закрытие VIPNotice: `(480,500)` → VIPNotice неактивна, обычная VIP-панель доступна.
4. Бесплатный сундук: `(705,267)` → CanGetFreeBox false и активна RoutineRewardsCollect.
5. Закрытие наград: `(480,500)` → окно исчезает; затем некоторое время активна CommonItemBagPage.
6. После завершения анимации: `(818,62)` → возврат городского HUD.

CommonItemBagPage в этом переходе — временная иконка сумки, куда летят предметы (`m_dislevel=2000`, поля MapHudPanel_*). Она разрешена только в контексте наблюдения перехода; предусловия следующего нажатия требуют её отсутствия. Настоящий неизвестный экран не разрешается автоматически.

Обычный `input tap` иногда не срабатывал. Для проверенных шагов применяется неподвижный touchscreen swipe на 100 мс с той же проверкой устройства и разрешения, что у обычного tap. По умолчанию остальные сценарии сохраняют прежнюю длительность.

## Ежедневные задания

- Открытие: `(30,155)`, ежедневная вкладка `(77,239)`, `curSelPanelType=2`.
- Готовые задания имеют `Stat=2`. После получения они удаляются из `DailyQuests`, а не переходят в `Stat=3`.
- Наблюдалось автоматическое получение всех 9 готовых заданий после одного нажатия `(755,255)`: QuestScores 0 → 52.
- Доступные сундуки имеют пороги 20/40/60/80/100 и `Completed=false`. Нажатие первого доступного сундука получило оба доступных сундука за 20 и 40; флаги обновились до появления RoutineRewardsCollect.
- Поэтому следующий ввод ждёт реального появления окна наград, а после его закрытия — завершения анимации CommonItemBagPage.
- `DailyCompleted` не используется как количество готовых заданий: после получения всех заданий оставалось значение 2, соответствующее двум доступным сундукам.
- При смене суток VIP обновился, но DailyQuests/QuestScores/NextRefreshTs сохранили старые данные. Открытие ежедневной вкладки за 8 секунд их не обновило. Проверка перезапуска игры вынесена в отдельный исследовательский инструмент.
- После перезапуска и отдельного нажатия Tap to Start загружен прежний персонаж, ежедневные данные обновились. Полный цикл через движок получил новую награду (0 → 10 очков) и вернулся в город. На устаревших данных сценарий ждёт без ввода. Для отдельных нажатий включены только проверенные сундуки за 20/40; кнопки 60/80/100 исключены до живой проверки.

Кандидаты сценариев и их подтверждённая регистрация находятся в `src/mirage/workflows.py`. Неподтверждённый кандидат не становится доступной задачей только из-за наличия кода и имитированных тестов.
